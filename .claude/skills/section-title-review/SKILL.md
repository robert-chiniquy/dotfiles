# Section title review

Read only the headings. An engineer skimming H1 then H2s should get the walk.

## Common Mistakes

- Reviewing body prose. Headings only.
- Mixing a concept-name H2 (`Residuation`, `Acquisition order`) with a claim H2 in the same post.
- Two headings for one node (`Five questions, one body` then `Five questions of one function`).
- A numbered sequence that drops its template (`One operator`, then `Lock order versus this code`).
- Headings that do not progress: what is in view, or how much of the program is in the table.
- Stamping every H2 as `A X is Y` because the last post did.
- A later H1 that re-introduces a concept an earlier H1 already named (`An if is a set` after `A condition is a set`).

## Pass

1. List H1, then H2s, then H3s under each H2.
2. Score H1: blog claim, not the concept name alone.
3. Score the H2 sequence: one register with the H1; each heading is a new object in view or a finer grain.
4. Score each numbered H3 run: one template, grain going up.
5. Propose retitles only where a heading fails. Do not invent a second walk.
6. Score the series H1s in publish order: each title introduces a concept or uses one already named. A later H1 that re-introduces `a set` or repeats `X is Y` after the set was named is a miss.

## Before finishing

- Heading list exists
- H1 is a claim
- H2s progress in one register
- Numbered H3s share a template
- No two headings for one node
